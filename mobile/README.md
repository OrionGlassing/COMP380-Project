# Frontend Tools / Dependencies:

Logic:
   zustand:
      - https://zustand.docs.pmnd.rs/learn/getting-started/introduction
      - Used for global state management, and easy device storage.
   AsyncStorage:
      - https://github.com/react-native-async-storage/async-storage
      - Used to store user data locally. (NOT ENCRYPTED, so not sensitive info)
   Expo SecureStore:
      - https://docs.expo.dev/versions/latest/sdk/securestore/
      - Used to store encrypted user data locally.
UI:
   React Native Size Matters:
      - https://github.com/nirsky/react-native-size-matters
      - The UI will not scale across different sized devices without manually
      correcting for the differences.
      - This library claims to make device scaling much easier.
   React Native Safe Area Context:
      - https://docs.expo.dev/versions/latest/sdk/safe-area-context/        
Components:
   React Native Community Slider:
      - https://www.npmjs.com/package/@react-native-community/slider
      - Slider component
   Expo checkbox:
      - https://docs.expo.dev/versions/latest/sdk/checkbox/
      - Simple checkbox component.
      - Being used purely as a visual component, not currently responsible for any logic.
   
   


# Data Architecture: 

   1. Zustand stores hold the data and handle device storage.
   2. Screens subscribe to specific pieces of stored data.
   3. Modular UI components display that data, and call update functions when changes are made.

Example explanation:

In componenets/sliders/LabeledSlider.tsx:
   - The labeled slider contains an array of strings that define the different possible selections.
   - So the useful data generated by the slider is the currently selected string.
   - But in order to set the slider to an initial value when it is rendered, it relies on the index of that string.
   - So we also need to save the index of the currently selected string.

In app/(protected)/customize-profile.tsx:
   - We create an instance of the labeled slider.
   - In this instance we define the callback function from the slider properties.
   - The reason we need the callback funciton to be an input is so that each
     instance of the slider can refer to unique data in the zustand store.
   - Speaking of th zustand store...
   - In this same file, we import the specific zustand store we are using, in this case
     we import useCustomizeProfileStore.
   - We then hook each piece of data that we need from the zustand store.
      - We need to hook each individually so that re-rendering is made efficient.
   - Then we use difficultyIndex and setDifficulty from the zustand store in the slider instance.

In utils/data-stores/customizeProfileStore.tsx:
   - This is the zustand store for ALL customize profile data.
   - We could have a unique store for each and every single component, but this will mean
     making and managing way too many indidivual stores.
   - Instead, we define stores that hold all of the data related to a specific domain.
      - In this case, we have the customize profile domain store.
      - We will add all data values that pertain to that in this file.
      - For now it's just the data from one component, but eventaually will be much more.
   - In the interface for the store, we define the necessary data and functions to control the data.
   - In the store itself we initialize the data (this will initialize from the data base later)
   - And we define the update function to update the data.
