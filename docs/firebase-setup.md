# Firebase / Firestore Setup Guide

This Document was created by Shiraz Boulgourjian.

This document explains the Firebase database and storage setup used for the recipe app. It also includes instructions for recreating the Firebase database environment and safely committing documentation changes to GitHub.

The app uses Firebase for:

- Firebase Authentication
- Cloud Firestore
- Firebase Storage

The main purpose of Firebase in this project is to manage user identity, store user-specific recipe data, store global recipe data, and store recipe image references.

---

# 1. Firebase Services Used

## 1.1 Firebase Authentication

Firebase Authentication is used to manage user accounts.

Passwords should not be stored in Firestore.

The Firebase user ID, also known as the UID, is used as the main identifier for user-specific data.

Example:

    profiles/{uid}

The `{uid}` value should match the Firebase Authentication UID for the user.

---

## 1.2 Cloud Firestore

Cloud Firestore is used to store structured app data, including:

- user profiles
- saved recipes
- global recipes

Firestore stores recipe information such as title, ingredients, directions, cook time, image path, and image URL.

---

## 1.3 Firebase Storage

Firebase Storage is used to store recipe image files.

Firestore does not store the actual image file.

Instead:

- Firebase Storage stores the image file.
- Firestore stores references to the image using `image_path` and `image_url`.

---

# 2. Firestore Structure

The app uses the following main Firestore structure:

    profiles/{uid}
    profiles/{uid}/saved_recipes/{recipeId}
    global_recipes/{recipeId}

---

# 3. User Profiles

## Path

    profiles/{uid}

## Purpose

Stores each user's profile and preference data.

## Example

    profiles/firebase_test_user

The document ID should match the Firebase Authentication UID for that user.

---

# 4. Saved Recipes

## Path

    profiles/{uid}/saved_recipes/{recipeId}

## Purpose

Stores recipes saved by a specific user in their personal cookbook.

## Example

    profiles/firebase_test_user/saved_recipes/pad_see_ew_001

## Fields

    recipe_id: string
    title: string
    ingredients: array
    directions: array
    cook_time: string
    image_path: string
    image_url: string

## Example Saved Recipe Document

    {
      "recipe_id": "pad_see_ew_001",
      "title": "Pad See Ew",
      "ingredients": ["rice noodles", "egg", "soy sauce"],
      "directions": ["Soak noodles.", "Cook egg.", "Stir fry noodles with sauce."],
      "cook_time": "25 minutes",
      "image_path": "recipe_images/pad_see_ew_001/pad-see-ew-sq-cu.jpg",
      "image_url": "<firebase-storage-image-url>"
    }

---

# 5. Global Recipes

## Path

    global_recipes/{recipeId}

## Purpose

Stores generated recipes outside the scope of a single user.

This allows the app to maintain a global collection of generated recipes in addition to each user's personal saved cookbook.

## Example

    global_recipes/pad_see_ew_001

## Fields

    recipe_id: string
    title: string
    ingredients: array
    directions: array
    cook_time: string
    image_path: string
    image_url: string
    created_by_uid: string
    created_at: timestamp

## Example Global Recipe Document

    {
      "recipe_id": "pad_see_ew_001",
      "title": "Pad See Ew",
      "ingredients": ["rice noodles", "egg", "soy sauce"],
      "directions": ["Soak noodles.", "Cook egg.", "Stir fry noodles with sauce."],
      "cook_time": "25 minutes",

      "image_url": "<firebase-storage-image-url>",
      "created_by_uid": "firebase_test_user",
      "created_at": "timestamp"
    }

# 6. Firebase Storage Structure

Recipe images are stored in Firebase Storage.

## Path Format

    recipe_images/{recipeId}/{imageFileName}

## Example

    recipe_images/pad_see_ew_001/pad-see-ew-sq-cu.jpg

The actual image file is stored in Firebase Storage.

Firestore stores references to the image using:

    image_path
    image_url

## Example Image Fields

    image_path: recipe_images/pad_see_ew_001/pad-see-ew-sq-cu.jpg
    image_url: <firebase-storage-image-url>

---

# 7. Image URL Explanation

Images generated by an AI model do not automatically have a permanent URL.

The general flow is:

1. The AI generates image data or an image file.
2. The backend receives that image.
3. The backend uploads the image to Firebase Storage.
4. Firebase Storage stores the image file.
5. The backend retrieves or generates a usable image URL.
6. Firestore stores the image reference.

The `image_path` field is the internal Firebase Storage path.

The `image_url` field is the URL the frontend can use to display the image.

---

# 8. Expected Data Flow

When a recipe is generated and saved, the recipe should be written to two Firestore locations:

## 8.1 User's Personal Saved Recipes

    profiles/{uid}/saved_recipes/{recipeId}

This stores the recipe in the user's personal cookbook.

## 8.2 Global Recipes Collection

    global_recipes/{recipeId}

This stores the recipe in the app-wide global recipes collection.

## 8.3 Recipe Image

The recipe image should be stored in Firebase Storage:

    recipe_images/{recipeId}/{imageFileName}

Both Firestore documents should include the same:

    image_path
    image_url

# 9. Replicating the Firebase Database Environment

These steps explain how to recreate the Firebase database environment for local development or for another team member setting up the project.

---

## Step 1: Create or Access the Firebase Project

Go to the Firebase Console:

    https://console.firebase.google.com/

Either:

- create a new Firebase project, or
- request access to the existing project from the project owner.

---

## Step 2: Enable Firebase Authentication

In the Firebase Console:

1. Open the project.
2. Go to **Build → Authentication**.
3. Click **Get Started**.
4. Go to the **Sign-in method** tab.
5. Enable the needed login providers.

For this app, the expected providers are:

    Email/Password
    Google

Firebase Authentication is responsible for managing user accounts.

User passwords should not be stored in Firestore.

---

## Step 3: Create the Firestore Database

In the Firebase Console:

1. Go to **Build → Firestore Database**.
2. Click **Create database**.
3. Choose **Production mode**.
4. Select a database location.
5. Finish setup.

Firestore will store the app’s structured data, including user profiles, saved recipes, and global recipes.

---

## Step 4: Create the Required Firestore Structure

Firestore is schema-less, so collections and fields are created when documents are added.

To recreate the structure manually, create sample documents using the following layout.

---

## Step 5: Create the User Profile Collection

Create a top-level collection:

    profiles

Create a test document using a Firebase UID as the document ID:

    profiles/{uid}

Example:

    profiles/firebase_test_user

This document stores user profile and preference data.

---

## Step 6: Create the Saved Recipes Subcollection

Inside a user profile document, create a subcollection:

    saved_recipes

Full path:

    profiles/{uid}/saved_recipes/{recipeId}

Example:

    profiles/firebase_test_user/saved_recipes/pad_see_ew_001

Saved recipe fields:

    recipe_id: string
    title: string
    ingredients: array
    directions: array
    cook_time: string
    image_path: string
    image_url: string

Example saved recipe document:

    {
      "recipe_id": "pad_see_ew_001",
      "title": "Pad See Ew",
      "ingredients": ["rice noodles", "egg", "soy sauce"],
      "directions": ["Soak noodles.", "Cook egg.", "Stir fry noodles with sauce."],
      "cook_time": "25 minutes",
      "image_path": "recipe_images/pad_see_ew_001/pad-see-ew-sq-cu.jpg",
      "image_url": "<firebase-storage-image-url>"
    }

---

## Step 7: Create the Global Recipes Collection

Create a top-level collection:

    global_recipes

Each generated recipe should also be stored here.

Full path:

    global_recipes/{recipeId}

Example:

    global_recipes/pad_see_ew_001

Global recipe fields:

    recipe_id: string
    title: string
    ingredients: array
    directions: array
    cook_time: string
    image_path: string
    image_url: string
    created_by_uid: string
    created_at: timestamp

Example global recipe document:

    {
      "recipe_id": "pad_see_ew_001",
      "title": "Pad See Ew",
      "ingredients": ["rice noodles", "egg", "soy sauce"],
      "directions": ["Soak noodles.", "Cook egg.", "Stir fry noodles with sauce."],
      "cook_time": "25 minutes",
      "image_path": "recipe_images/pad_see_ew_001/pad-see-ew-sq-cu.jpg",
      "image_url": "<firebase-storage-image-url>",
      "created_by_uid": "firebase_test_user",
      "created_at": "timestamp"
    }

---

## Step 8: Enable Firebase Storage

Firebase Storage is used for recipe images.

In Firebase Console:

1. Go to **Build → Storage**.
2. Click **Get Started**.
3. Select a location.
4. Finish setup.

Once Storage is enabled, recipe images should follow this path format:

    recipe_images/{recipeId}/{imageFileName}

Example:

    recipe_images/pad_see_ew_001/pad-see-ew-sq-cu.jpg

---

## Step 9: Upload a Test Recipe Image

In Firebase Console:

1. Go to **Build → Storage**.
2. Open the **Files** tab.
3. Upload a test image.
4. Store it using this path format:

    recipe_images/{recipeId}/{imageFileName}

Example:

    recipe_images/pad_see_ew_001/pad-see-ew-sq-cu.jpg

---

## Step 10: Copy or Generate the Image URL

After uploading the image:

1. Click the uploaded image in Firebase Storage.
2. Copy the image URL or download URL.
3. Store that URL in Firestore as `image_url`.

The Firestore document should also store the internal path as `image_path`.

Example:

    image_path: recipe_images/pad_see_ew_001/pad-see-ew-sq-cu.jpg
    image_url: <firebase-storage-image-url>

# 10. Backend Firebase Admin Setup

The Django backend needs Firebase Admin SDK access in order to read and write to Firebase services.

The backend developer will need:

    Firebase project ID
    Firebase Storage bucket name
    Firebase Admin SDK service account key

The service account key can be downloaded from:

    Firebase Console → Project Settings → Service Accounts → Generate New Private Key

The service account key should be stored locally or in a secure backend environment.

It should not be committed to GitHub.

---

When a recipe is generated and saved, the backend should write the recipe to two Firestore locations:

    profiles/{uid}/saved_recipes/{recipeId}
    global_recipes/{recipeId}

The recipe image should be stored in Firebase Storage:

    recipe_images/{recipeId}/{imageFileName}

Both Firestore documents should store the same:

    image_url

# 12. Local Developer Checklist

A developer has replicated the Firebase database environment correctly if:

- Firebase Authentication is enabled.
- Firestore Database is created.
- Firebase Storage is enabled.
- The `profiles` collection exists.
- A user document can contain a `saved_recipes` subcollection.
- The `global_recipes` collection exists.
- Recipe image files can be stored under `recipe_images/{recipeId}/`.
- Saved recipe documents include `image_path` and `image_url`.
- Global recipe documents include `image_path` and `image_url`.

# 13. Security Notes

Do not commit Firebase Admin SDK service account keys to GitHub.

Do not upload:

    firebase-service-account.json
    .env
    secrets/
    Secrets/

The Firebase service account key should only exist locally or in a secure backend environment.

The frontend should never receive or use the Firebase Admin SDK service account key.

# 15. Safely Committing This Documentation to GitHub

These steps explain how to commit this file without accidentally committing secrets or unwanted backend changes.

---

## Step 1: Check Git Status

From the project root, run:

    git status

Review the output carefully.

Do not commit files such as:

    backend/Secrets/
    secrets/
    firebase-service-account.json
    .env
    .venv/
    backend/.venv/
    *.lnk

---

## Step 2: Do Not Use `git add .`

Avoid this command:

    git add .

This can accidentally stage secret files, environment files, backend settings, virtual environments, or local shortcuts.

Instead, stage only the specific safe files.

---

## Step 3: Stage Only This Documentation and `.gitignore`

Run:

    git add docs/firebase-setup.md .gitignore

This stages only the Firebase setup documentation and `.gitignore`.

---

## Step 4: Check What Is Staged

Run:

    git status

Look under:

    Changes to be committed:

You should only see:

    docs/firebase-setup.md
    .gitignore

If you see anything else, stop before committing.

---

## Step 5: View the Exact Staged Changes

Run:

    git diff --staged

Review the output.

Make sure the staged changes do not include:

    private_key
    client_email
    firebase-service-account
    .env
    password
    secret
    backend/Secrets/
    firebase-service-account.json

If any secret appears, do not commit.

---

## Step 6: Unstage a File If Needed

If you accidentally staged a file you do not want to commit, use:

    git restore --staged path/to/file

Example:

    git restore --staged backend/Secrets/firebase-service-account.json

Then check again:

    git status
    git diff --staged

---

## Step 7: Commit the Safe Files

Once only the safe files are staged, run:

    git commit -m "Add Firebase setup documentation"

---

## Step 8: Push the Commit

Run:

    git push

If Git says there is no upstream branch, check the current branch:

    git branch

Then push using the current branch name.

Example for branch `Stefan`:

    git push -u origin Stefan

---

# 16. Summary

The Firebase database environment should use the following main structure:

    profiles/{uid}
    profiles/{uid}/saved_recipes/{recipeId}
    global_recipes/{recipeId}
    recipe_images/{recipeId}/{imageFileName}

The user-specific saved recipe and the global recipe should both reference the same image using:

    image_path
    image_url

This keeps user cookbook data, global recipe data, and image storage organized while allowing the backend and frontend to reference the same recipe image consistently.
